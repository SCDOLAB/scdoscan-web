EN How contract verification works

Steps

  1. Deploy your contract on SCDO Mainnet (Shard 0), chainId 5680 (RPC https://scdoscan.io/rpc/0), and note the contract address and the deployment transaction.
  2. Collect your build settings: the exact solc compiler version, whether the optimizer was on and how many runs, the evmVersion, and the constructor arguments. Your build tool (Hardhat, Foundry, Remix, Truffle) shows these.
  3. Prepare the source: either one flattened .sol file, or the solc standard JSON input (recommended for multi-file projects).
  4. Open the request form with the green button above and fill in every field. The form is a public GitHub issue, so never paste private keys, seed phrases or passwords.
  5. Manual review by the SCDO team. We compile your source with exactly the settings you gave and compare the result with the code stored on chain (eth_getCode), byte for byte. We reply in the issue if anything is missing or does not match.
  6. Published on the explorer. When the code matches, the contract's address page on scdoscan.io shows a "Contract: Verified" badge, the source code, the ABI and the compiler settings, plus a Read/Write contract panel. Your browser also re-checks the on-chain code hash live each time the page is opened.

What the form asks for

Contract address0x + 40 hex characters
ChainSCDO Mainnet (Shard 0), chainId 5680
Compiler versione.g. v0.8.24+commit.e11b9ed9
Optimizer & runsenabled / disabled, runs (usually 200)
evmVersione.g. paris, shanghai, or compiler default
Sourceflattened file or standard JSON input
Constructor argsABI-encoded hex, or "none"
LicenseSPDX identifier, e.g. MIT
Contactemail or Telegram (shown publicly)

Good to know

  • Only an exact match is published (the trailing metadata hash included). A metadata-only difference is a "partial" match and is not published by default.
  • Contracts with immutable variables, linked libraries or proxies may need extra details; add them in the "Notes" field.
  • Verification is free. The team will never ask you for keys, seed phrases or a payment.
  • Contracts on the archived legacy shards 1–4 are not covered by this process.
  • How we check, and how to reproduce it yourself: /verified/METHOD.txt.

中文 合约验证流程

步骤

  1. 部署合约：在 SCDO Mainnet (Shard 0)（chainId 5680，RPC https://scdoscan.io/rpc/0）上部署合约，记下合约地址和部署交易哈希。
  2. 整理编译参数：准确的 solc 编译器版本、是否开启优化器及 runs 次数、evmVersion、构造函数参数。可在 Hardhat、Foundry、Remix、Truffle 等工具中查看。
  3. 准备源码：一个展平后的 .sol 单文件，或 solc 标准 JSON 输入（多文件项目建议使用）。
  4. 打开申请表：点击上方绿色按钮，填写所有字段。申请表是公开的 GitHub issue，请勿填写私钥、助记词或密码。
  5. SCDO 团队人工审核：我们按照你填写的参数编译源码，并与链上代码（eth_getCode）逐字节比对。如有缺漏或不一致，会在 issue 中回复。
  6. 在浏览器中公开：比对一致后，scdoscan.io 的合约地址页面会显示 "Contract: Verified" 标记、源码、ABI 和编译参数，并提供读/写合约面板。每次打开页面时，浏览器还会实时复核链上代码哈希。

申请表需要填写

合约地址0x + 40 位十六进制
链SCDO Mainnet (Shard 0)，chainId 5680
编译器版本例如 v0.8.24+commit.e11b9ed9
优化器与 runs开启 / 关闭，runs（通常为 200）
evmVersion例如 paris、shanghai 或编译器默认
源码展平单文件或标准 JSON 输入
构造函数参数ABI 编码的十六进制，或填 "none"
许可证SPDX 标识，例如 MIT
联系方式邮箱或 Telegram（公开显示）

注意事项

  • 只有完全一致（包括末尾的元数据哈希）才会公开。仅元数据不同属于"部分匹配"，默认不公开。
  • 含 immutable 变量、链接库或代理合约的，可能需要补充信息，请写在"备注"中。
  • 合约验证免费。团队不会向你索要私钥、助记词或任何付款。
  • 已归档的旧分片 1–4 上的合约不适用本流程。
  • 验证方法及自行复现方式：/verified/METHOD.txt。
