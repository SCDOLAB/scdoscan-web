Shard0 load test, 2026-09-28 Load test

SCDO shard0 · core-geth Ethash PoW · chainId 5680

On 2026-09-28 between 23:22 and 23:33 (UTC+8) we ran a stepped throughput test on shard0. It sent 39,377 simple transfers: EIP-1559 self-transfers of 1 wei (21,000 gas each) from the shard0 faucet 0x42c4854A…c0e4 back to itself. They are in blocks 3430–3489. The fees came to about 0.0085 SCDO and went to our own miner. No funds were created and no user accounts were involved.

These transactions are tagged Load test and are hidden from the default transaction lists: the homepage "Latest Transactions" for Shard 0 and the faucet's address page. They stay indexed and can still be looked up:

  • Any single tx page, e.g. 0x80b12fc8c6fa3aba…. The page shows the Load test tag.
  • The faucet address page has a "show them" link under the Shard0 Transactions table.
  • API: /enhance/shard0/txs?loadtest=1, /enhance/shard0/address_txs?addr=0x42c4…c0e4&loadtest=1, /enhance/shard0/tx?hash=<txhash> (field "tag":"loadtest").
  • Rule: /labels.json → txTags.loadtest. It matches from = to = faucet, value = 1 wei, no calldata, blocks 3400–3500.

What this means: shard0 sustains about 90–100 TPS of simple transfers today. The hard cap is 30M gas ÷ 21,000 = 1,428 transfers per block, which is about 110 TPS at the 13 s block target. Token transfers (35–50k gas) would reach about half that. Blocks are sometimes not full even with a backlog. This is because a PoW block found 1–5 s after the previous one only holds the transactions that were in the sealing template at that moment.

Test tool: a small Go sender run on the node host against its local RPC. It stops itself automatically at >20% RPC errors or when the backlog exceeds the txpool limit.
